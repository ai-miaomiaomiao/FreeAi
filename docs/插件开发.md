# 插件开发

**一句话：插件永远不改内核。** 在 `src/plugins/` 下建一个文件夹，放一个 `__init__.py`，声明几个模块级常量，内核下次扫描就会认识它。

## 目录与命名

```
src/plugins/
  myplugin/
    __init__.py        ← 唯一必需文件
    web/               ← 可选：插件自带的前端 js/css，由 WEB 声明
      panel.js
      panel.css
```

- **一个文件夹一个插件**，文件夹名就是插件身份 —— 禁用清单、静态资源 URL、前端判断一律用它
- `__init__.py` 里 `NAME` 建议与文件夹名一致；不一致时 `NAME` 也能用来调接口，但**别混用**（`auto_code` 的 NAME 是 `autoCode`，它就是个历史遗留的反例）
- `_shared/` 是被各插件 import 的公共库，不是插件

## 一个插件能声明什么

全部都是模块级常量，**不写也能跑**，写了内核就多认一项：

| 常量 | 类型 | 作用 |
| --- | --- | --- |
| `NAME` | `str` | 插件名，缺省取文件夹名 |
| `DESCRIPTION` | `str` | 一句话简介，界面上显示 |
| `SCHEMA` | `dict` | **一个** OpenAI function 定义 —— 声明后智能体就能调用这个工具 |
| `run` | `def` | `SCHEMA` 对应的执行入口 |
| `VIEWS` | `list` | 左侧活动栏的视图入口 |
| `ACTIONS` | `list` | 编辑器标题栏上「对当前文件做点什么」的按钮 |
| `EXPOSE` | `dict` | 暴露给前端的 HTTP 接口 |
| `WEB` | `dict` | 插件自带的前端 js / css（文件放 `<插件>/web/` 下） |
| `EDITOR` | `dict` | 对编辑器声明扩展名能力：染色、可运行、文件树字母标识 |
| `TOOL_CAPS` | `dict` | 给工具声明「能力」，让内核按能力而非按名字找工具 |

### 没有 `TOOLS` 声明

一个插件只有**一个** `SCHEMA`，不是工具字典表。需要多功能就在 `parameters` 里用 `action` 枚举分发，`run()` 内部 switch —— 这也是仓库自带插件的统一写法（比如 `run_script` 有 `run` / `recent`）。

```python
NAME = "myplugin"
DESCRIPTION = "演示插件"

SCHEMA = {
    "type": "function",
    "function": {
        "name": "my_tool",                 # 工具名，全局唯一，别和内置工具重名
        "description": "这个工具做了什么、有什么客观后果",
        "parameters": {
            "type": "object",
            "properties": {
                "action": {"type": "string", "enum": ["do", "list"]},
                "path": {"type": "string", "description": "目标路径"},
            },
            "required": ["action"],
        },
    },
}

def run(args: dict, ctx: dict) -> dict:
    action = str((args or {}).get("action") or "").strip().lower()
    if action == "list":
        return {"ok": True, "summary": "共 3 项", "content": "..."}
    return {"ok": False, "summary": "未知 action", "content": "action 只认 do / list"}
```

### `run(args, ctx)` 的约定

- **返回值必须是 dict**，否则内核判错（`ok: False`）。建议固定给三个键：
  - `ok`：成功与否
  - `summary`：一行短结论，界面折叠时显示这个
  - `content`：给模型看的正文，可长
- 抛异常不会炸掉整轮对话：内核捕获 `BaseException` 并转成 `ok: False`。但**自己兜住更好** —— 你比内核清楚该怎么降级
- `ctx` 是内核给的运行上下文（只读，别改）：

| 键 | 含义 |
| --- | --- |
| `workspace` | 当前工作区根目录；远程工作区时是 `ssh://...` |
| `roots` | 允许访问的根目录列表 |
| `ai_dir` | 当前工作区的数据目录 |
| `session_id` | 会话 id（写状态、记改动时带上） |
| `should_cancel` | 取消信号，长循环里可以查 |

⚠️ `ctx` 里的 `workspace` **可能是 `ssh://` 开头的远程路径**。要落地到本地文件时先判断，别直接 `open()`。

### `VIEWS` —— 活动栏图标

```python
VIEWS = [
    {"view": "mytool", "icon": "🔧", "title": "我的工具",
     "after": "files",            # 排在哪个内置视图后面
     "hidden": False,             # True = 不占活动栏，从 ⚙ 设置菜单进
     "detect": {"files": ["build.gradle", "gradlew"], "depth": 2}},
]
```

- `view` **必须和前端对上**：前端据此找 `<div id="viewXxx">` 和 init 钩子，随便起名字只会得到一个空面板
- `plugin` 字段不用写，内核统一填文件夹名
- `after` 控制排位（比如 `"svn"`、`"files"`）
- `detect` 让图标**只在当前工作区确实是那种工程时才出现**（有 `gradlew` 才显示 🐘）。`files` / `dirs` / `any` 是名字列表（**不许带路径分隔符**），`depth` 是扫描层数，`up` 向上找几层。不写 = 永远显示

### `ACTIONS` —— 编辑器顶栏按钮

```python
ACTIONS = [
    {"action": "run", "label": "▶ 运行", "title": "运行这个脚本",
     "when": "script", "order": 10, "toggle": False},
]
```

- `action` 必须和前端 `PLUGIN_ACTIONS[id].click` 对上
- `when` 只认前端预设的几个关键字：`script` / `markdown` / `always`
- `order` 小的靠左，默认 100；`toggle: true` 用于预览这类需要「按下高亮」的按钮

## `EXPOSE` —— 给前端的 HTTP 接口

```python
EXPOSE = {
    "recent": "返回最近跑过的脚本",
    "mark":   "把脚本记进最近列表",
}

def recent(payload):          # ← 只收一个位置参数
    return {"scripts": []}
```

- URL 是 `/api/plugin/<文件夹名>/<函数名>`，NAME 与文件夹名**两种写法都认，但请统一用文件夹名**
- 字典的**值只是一行说明**，不是 schema
- 函数**必须能只收一个位置参数**：内核按位置传 `fn(payload or {})`，**不传 `ctx`**。要从参数里拿工作区，自己从 `payload` 里取
- 返回值被内核包一层：成功 `{"ok": true, "result": ...}`，抛异常则 HTTP 400 `{"error": "..."}`。所以**前端读 `r.result`**，不是读你返回的顶层字段

## `WEB` —— 插件自带的前端资源

```python
WEB = {"js": ["panel.js"], "css": ["panel.css"], "load": "always"}
```

- 文件放 `<插件>/web/` 下，内核以 `/plugin-asset/<文件夹名>/<文件名>` 发出去；前端按 `/api/plugins` 的返回自动插 `<script>` / `<link>`
- **键必须是文件夹名**：那条路由是照目录名找磁盘文件的，写 `NAME`（例如 `autoCode`）会 404
- `load: "always"` = 插件启用就加载，即使它没声明任何 `VIEWS`；不写则跟随该插件的 `VIEWS` / `ACTIONS` 入口
- 为什么单独一个常量、不散在 `VIEWS` 里写 `"js": "x.js"`：`md_preview`、`xml_preview` 这类**只有顶栏按钮、没有视图**的插件，资源没地方挂
- 好处也彻底：插件被禁用就不 import，`WEB` 读不到，前端自然不会去加载它那几百行 js

## `EDITOR` —— 编辑器认哪些扩展名

```python
EDITOR = {
    "exts": ["kt", "kts"], "func": "highlight",   # 染色：前端调 EXPOSE 里的 func
    "run_exts": ["py", "bat"], "action": "run",   # 可运行：顶栏出现 ▶
    "icons": {"kt": "K"},                          # 文件树里的字母标识（1-2 字符）
    # "complete_func": "complete",                 # 可选：代码补全入口
}
```

- 前端只认字段、不认插件名，所以加一门语言不用改内核
- 染色的 `func` 必须同时列进 `EXPOSE` —— 前端就是按 `/api/plugin/<文件夹名>/<func>` 调的
- `action` 对应 `ACTIONS` 里的某个 `action` id
- 多个插件抢同一个扩展名时**按文件夹名排序、先到先得**（图标和染色用同一个赢家，免得对不上）

## `TOOL_CAPS` —— 按能力找工具

```python
TOOL_CAPS = {"my_tool": ["screenshot"]}
```

内核里有几处需要「找个能截图的工具」，写死工具名会在插件改名时静默失效。声明能力后调用方用 `find_by_cap("screenshot")` 找，找不到就走降级分支。绝大多数插件不需要这个。

## 三条硬约束

1. **不改内核。** 需要的新能力先在插件里实现，重复出现了再考虑提到内核
2. **import 时不要干重活。** 插件加载是 import，模块顶层跑耗时操作会拖慢服务启动和热加载。把工作放进 `run()` / `EXPOSE` 函数里
3. **不要写绝对路径。** 工作区数据统一落 `<工作区>/.ai/temp/<插件名>/`（可用 `from .._shared import wsdata`），别写到源码目录里

## 调试

- 改完**插件代码**不用重启服务：热加载按 `plugins/` 下所有 `.py` 的 (mtime, size) 指纹判断，变了才重扫重载（每次把工具表发给模型之前都会比一次）
- 但这只覆盖插件目录：改 `src/` 里的**内核**代码（`web_agent.py`、`agent_actions.py` …）仍然必须重启服务
- 加载失败不会静默：错误进 `/api/plugins` 的 `load_errors`，界面「设置 → 插件」能看到
- 禁用某个插件：写进 `.ai/plugins_disabled.json`，被禁的插件**压根不会被 import**，它的工具/视图/接口一并消失（这比前端隐藏按钮彻底）
